# Insta360 X5、Husky A200 与 Quest 3 项目说明

## 1. 项目目标

把 Insta360 X5 安装在 Clearpath Husky A200 机器人上，让远程用户通过 Meta Quest 3 看到机器人周围的实时 360°画面。

最终的数据流如下：

```text
Insta360 X5
    ↓ USB
Husky A200车载电脑
    ↓ 读取并拼接360°画面
WebRTC网络传输
    ↓
Quest 3中的Unity程序
    ↓
用户转头查看机器人四周
```

目前已经完成前半部分：

```text
X5 → Husky → 实时读取 → 360°拼接 → 1920×960、30 FPS
```

WebRTC发送和Quest 3接收是下一阶段。

## 2. 使用了什么技术

### Insta360 Camera SDK

用途：让Husky识别并控制X5，同时取得相机的实时原始视频。

简单理解：它负责“从相机拿到画面”。

### Insta360 Media SDK

X5有前后两个鱼眼镜头。Media SDK把两个鱼眼画面拼成一张完整的360°画面。

简单理解：它负责“把两只镜头合成一个360°世界”。

输出格式为等距柱状投影，也叫 Equirectangular：

```text
宽度：1920
高度：960
帧率：约30 FPS
```

这张图看起来是横向展开的，但放到Unity球体内部后，用户可以转头观察四周。

### Docker

Husky原系统是 Ubuntu 20.04，但Insta360 Linux Media SDK要求Ubuntu 22.04环境。

因此没有修改Husky原系统，而是在Husky上运行一个Ubuntu 22.04 Docker容器。

简单理解：Docker是在Husky里面创建了一个独立的软件运行环境，不会替换机器人的原系统。

### NVIDIA GPU、CUDA、OpenGL和EGL

Husky车载电脑有一张 NVIDIA GeForce GTX 1650。

它用于加速360°画面处理。Media SDK通过OpenGL/EGL建立图形处理环境。

CUDA容器版本为：

```text
nvidia/cuda:11.7.1-devel-ubuntu22.04
```

Husky的NVIDIA驱动版本较新，可以向下兼容CUDA 11.7。

### C++

Husky上的相机程序使用C++编写，因为Insta360 Linux SDK提供的是C++接口。

程序完成以下工作：

1. 搜索X5。
2. 打开X5。
3. 启动实时视频。
4. 接收双鱼眼视频、陀螺仪和曝光数据。
5. 调用Media SDK拼接画面。
6. 统计拼接分辨率和帧率。

### WebRTC（下一阶段）

WebRTC将用于把Husky生成的360°视频低延迟发送到Quest 3。

简单理解：它负责“通过网络实时传视频”。

后续预计的数据流：

```text
360°拼接帧
    ↓
NVIDIA硬件H.264编码
    ↓
WebRTC
    ↓
Unity WebRTC接收
    ↓
Quest 3显示
```

### Unity与Meta Quest 3（下一阶段）

Unity接收到视频后，会把1920×960画面贴到一个球体的内表面。

Quest 3用户位于球体中心，因此：

- 向左转头可以看左侧；
- 向右转头可以看右侧；
- 抬头可以看上方；
- 低头可以看下方。

Quest 3中看到的是完整360°环境，不是两个圆形鱼眼画面。

## 4. 准备的项目文件

Husky项目目录：

```text
/home/administrator/HuskyInsta360
```

主要文件：

```text
HuskyInsta360/
├── CMakeLists.txt
├── Dockerfile
├── docker-compose.yml
├── nvidia-egl.json
├── sdk/
│   ├── CameraSDK-2.1.1-Linux.tar.gz
│   └── libMediaSDK-dev-3.1.1.0-amd64.tar.xz
└── src/
    └── camera_stitch_test.cpp
```

文件用途：

- `Dockerfile`：建立Ubuntu 22.04、CUDA和SDK环境。
- `docker-compose.yml`：设置GPU、USB、网络和图形权限。
- `nvidia-egl.json`：让Media SDK选择NVIDIA EGL，而不是Mesa。
- `CMakeLists.txt`：编译C++程序。
- `camera_stitch_test.cpp`：相机读取与360°拼接测试程序。
- `sdk/`：存放Insta360 Linux Camera SDK和Media SDK。

## 5. 已完成的部署步骤

### 第一步：确认Husky系统

```bash
uname -m
cat /etc/os-release
lspci | grep -i -E "vga|3d|nvidia"
nvidia-smi
```

确认结果为x86_64、Ubuntu 20.04和GTX 1650。

### 第二步：确认Docker与GPU容器

```bash
docker --version
docker run --rm --gpus all \
  nvidia/cuda:12.2.2-base-ubuntu22.04 \
  nvidia-smi
```

容器成功识别GTX 1650。

### 第三步：复制项目和SDK

项目复制到：

```text
/home/administrator/HuskyInsta360
```

验证：

```bash
ls -lh ~/HuskyInsta360
```

### 第四步：构建Docker镜像

```bash
cd ~/HuskyInsta360
docker compose build
```

生成的镜像：

```text
husky-insta360:test
```

### 第五步：连接X5

1. 用支持数据传输的USB线连接X5和Husky。
2. 打开X5。
3. 确认Linux识别相机：

```bash
lsusb
```

成功结果包含：

```text
2e1a:0002 Arashi Vision Insta360 X5
```

### 第六步：解决NVIDIA EGL问题

最初容器只能看到Mesa EGL配置，因此Media SDK无法建立GPU拼接环境。

加入了：

```text
nvidia-egl.json
```

并将Husky的X11显示和LightDM授权目录挂入容器：

```text
/tmp/.X11-unix
/var/run/lightdm/root
```

这样Media SDK可以使用Husky的NVIDIA OpenGL/EGL。

### 第七步：运行测试

```bash
cd ~/HuskyInsta360
docker compose run --rm insta360-test
```

停止测试：

```text
Ctrl+C
```

## 6. 测试成功的判断标准

程序成功找到相机：

```text
Found: Insta360 X5
Live preview started
```

程序持续输出：

```text
stitched=1920x960 fps=30
```

这表示：

- X5与Husky之间的USB通信正常；
- Camera SDK能够读取实时视频；
- Media SDK能够处理双鱼眼数据；
- NVIDIA GPU图形环境正常；
- 已生成完整的360°拼接画面；
- 帧率稳定在约30 FPS。

## 7. 当前警告说明

程序可能显示Vulkan、陀螺仪时间戳或初始H.264解码警告。

目前它们不会阻止画面输出，因为：

```text
stitched=1920x960 fps=30
```

已经证明拼接程序正在稳定工作。

如果之后画面出现明显抖动、接缝错误或帧率下降，再单独处理这些警告。
